B. CODE-ONLY PARITY WORK, IN PRIORITY ORDER

1. P08 - General HashedPatchMap and the remaining inventory paths (highest unblocked risk)
   - Implement outbound encoding for arbitrary server-provided component values, not only the 405
     Creative catalogue patches.
   - Implement the native HashedPatchMap hash for arbitrary components. The native client uses
     HashOps.CRC32C over the component's CODEC encoding, so this needs canonical per-component
     hash encoding, not CRC of the network bytes.
   - Use the same native stack path for Creative writes and normal container clicks; remove the
     creativePatch/creativeHashes special cases once general encoding exists.
   - Verify click state IDs and rejection/resync when the server rejects a patched stack.
   - Inventory edge cases: shift-click into a full container, patched stacks into every slot type,
     number-key/offhand swaps, drag distribution and double-click collection.
   - Live-accept merchant, enchanting, stonecutter and loom windows (screens exist; end-to-end menu
     flows do not).

2. P06 - Live triggers and remaining scope decisions

     post-effects and bundle paths against a real server.
