Closed in this batch:
- Server-decoded component patches preserve their exact network bytes for normal container
  clicks; predicted damage updates only its own row. Integer components now use exact native
  HashOps.CRC32C values, and enchantment/stored-enchantment maps use the native string/map
  HashOps encoding (all 128 native catalogue maps match), while other unknown hashes use the
  verified empty-HashedPatchMap resync fallback instead of throwing from the click sender. Patch
  stacking ignores transport bytes.
- Off-hand number-key swaps (button 40), drag distribution, pickup-all and full-container
  shift-click have direct 26.3 inventory coverage.
- Native 26.3 RecipeDisplay-graph recipe book: all 13 categories map to tabs; SlotDisplay
  item/item_stack/tag/composite/remainder/fuel branches resolve to stacks; shaped grids keep
  width/height and empty cells; shapeless/furnace/stonecutter/smithing displays become book
  records; add/replace/remove rebuilds the view; entry flags 1/2 drive notification/highlight;
  seen display ids stay seen; and the server ghost display drives the grid ghost.
- Native recipe-book senders now use RecipeDisplayId VarInts for place_recipe and seen_recipe
  (the old string bodies were the 1.20.6 layout), and place_ghost_recipe resolves its native
  RecipeDisplay instead of reading the absent legacy `recipe` field.
- Native chat click parity: clickable styles are right-click only, shift-right-click applies the
  style insertion, run_command uses the unattended command packet with optional slash trimming,
  suggestions apply from any mouse button, and the suggestion rect consumes blank clicks.
- Focused tests added: test-recipe-displays-26.3.mjs and five chat-routing cases in
  test-chat-click-actions-26.3.mjs.
- Native shadowRadius = 0 is now respected for cushions and ominous item spawners.
  CushionRenderer and OminousItemSpawnerRenderer do not set shadowRadius, while
  ItemEntityRenderer still uses 0.15; test-small-entities-26.3.mjs pins both sides.
- The wind-charge scrolling texture now samples with repeat wrapping, matching
  RenderTypes.breezeWind; clamp-to-edge would smear the UV scroll at the texture border.
- Added two focused tests: wind-charge repeat sampling and native small-entity shadow rules.

1. P08 - General HashedPatchMap and the remaining inventory paths (LARGE, highest unblocked risk)
   Status: partial. The 405 Creative catalogue patches are encoded and hashed, and server-decoded
   patches now preserve their exact bytes with a verified resync fallback for unknown hashes. The
   general canonical hash path is still not implemented.
   Remaining:
   - Encode arbitrary server-provided component values, not only the Creative catalogue patches.
   - Implement the native HashedPatchMap hash for arbitrary components. The native client uses
     HashOps.CRC32C over the component's CODEC encoding, not a CRC of the network bytes. This
     requires canonical per-component hash encoding.
   - Use one native stack path for Creative writes and normal container clicks, then remove the
     creativePatch/creativeHashes special cases.
   - Verify live click state IDs and the server resync path for a patched stack with an empty hash
     map.
   - Inventory edge cases: shift-click into a full container, patched stacks into every slot type,
     number-key/offhand swaps, drag distribution and double-click collection.
   - Live-accept merchant, enchanting, stonecutter and loom windows.
   Do not fake a hash to make a test pass. Wrong hashes only trigger server resyncs, so a fake
   value hides a real correctness gap.
