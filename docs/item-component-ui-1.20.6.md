# Native component item UI integration

The codec preserved modern components, but the item UI and several use/render helpers still read legacy slot NBT or empty Creative metadata. A damaged sword could decode with damage 37 and then display as undamaged; custom names, potion colors and other component values were similarly lost at the consumer boundary.

`Items` now reads effective defaults, additions and explicit removals directly. The runtime consumers cover names/rarity/lore, damage and maximum durability, unbreakable state, per-stack maximum size, enchantment lookup/order, attributes, food/use animation/duration, potion effects/colors, spawn-egg colors, instrument durations, glint overrides and several additional tooltip rows. Item rendering reads component colors and model predicates; inventory/Creative/merchant limits, trident checks and elytra durability pass the complete stack. No legacy slot NBT is fabricated.

`ExtractItemUx1206.java` executes the pinned client's real ItemStack codec, normal/advanced tooltip methods, ItemColors, use actions/durations and rarity/glint methods. It also extracts metadata for all 1,330 items, 46 potions, effects, spawn eggs and instruments, including native attribute defaults and enchantment tooltip order. The source client and official mappings are hash-verified; all 8,206 oracle class files match the original jar.

The 49 native stack cases cover defaults, removals, renamed items, hidden rows, custom durability/stack limits, enchantments, lore, potions (including hours and infinity), dyes, inline instruments, charged projectiles, glint overrides and attributes. Tests compare text and the visible characters' colors/italics/decorations, plus tint functions, item predicates, durability overlays and actual inventory click limits. All 1,330 default item actions, durations and glint values are checked. Native enchantment-map entry order can vary between JVM runs: regeneration compares that map semantically while retaining a real native wire fixture. Each retained fixture still byte-round-trips through the JS codec.

Run `npm run item-ux:1.20.6` to regenerate and `npm run test:1.20.6` to check the native oracles and target regressions. The existing native model extraction prepares the unsigned oracle cache; use a JDK 21+ compiler/runtime or the `JAVA` / `JAVAC` overrides.

This is **not full item parity**. Native metadata/API comparisons do not replace graphical acceptance on every GUI/held/dropped path. Container contents, bundles, books, profiles, banners/armor trims, custom registry ownership, tool-rule gameplay, food/cooldown/use conditions and several special item behaviors remain on the checklist. Normal/advanced tooltip fixtures use the native null-player context; the live player's base-attribute integration still needs native graphical acceptance. Component setters must also keep effective-value views coherent; this batch adds read-only consumers, not a general mutation API.

## Version review

Component-based item routing starts in 1.20.5 and must not be copied into 1.19.4 or earlier. Older targets already retain their own item metadata/NBT paths. A shared potion tooltip defect was found during the review: native 1.19.4 already uses padded minutes/hours and the translated infinity label. That fix and localized amplifier/duration templates are backported on branch 1.19.4 in `d7fdfe7`, with six real Java formatter fixtures and 23 related checks. Follow-up shared infinity/order presentation fixes are in `c633317` (verification note `9ce5e0c`). Native 1.14.4–1.18.2 formatter classes retain the earlier minute format. The 1.19.4 [official release notes](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-19-4) confirm infinite effects; the Wiki fetch was unavailable, and exact behavior was checked against the pinned native classes.
