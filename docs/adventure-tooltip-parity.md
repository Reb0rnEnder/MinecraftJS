# Adventure tooltip and registry parity follow-up

2026-11-15. This batch fixes native permission descriptions across all ten supported branches, plus older Adventure predicate parsing and target-specific 1.20.6 tag drift. Full client parity remains unaccepted; this is a scoped follow-up to the preceding component-permission implementation.

## Behavior fixed

- Items now show native Can Break / Can Be Placed On sections, blank separators, gray headers, dark-gray block names, native malformed-name fallback and release-specific list ordering. Older releases also gain the missing blue Unbreakable line.
- Native block description IDs are extracted from each target, retaining aliases such as wall torches and translated legacy metadata names. Block/item registries are kept separate.
- Typed NBT lists and numeric HideFlags getters control old tooltips. Numeric byte/short/int/long/float/double tags are recognized; string flags are ignored. The native hide bits for permission sections, Unbreakable, and already implemented enchantment/attribute sections are honored. This does not certify every other legacy HideFlags section.
- 1.8.9 keeps case-sensitive block paths; 1.12.2 lowercases them. Both retain native signed/Unicode decimal IDs and out-of-range numeric fallback to air. The same resolver is used for actual Adventure permissions, fixing the previous mismatch.
- From 1.13.2, exact integer properties are parsed via native Integer.parseInt semantics and checked against the property's domain. Thus `wheat[age=04]` and `wheat[age=+4]` match age 4, while age 8 does not. Tooltips and actual permission checks share this behavior. Single-quote parsing and empty-tag behavior retain release differences.
- 1.20.6 components flatten holders, remove duplicates, preserve native order and show the gray unknown-use entry when any predicate is unrestricted. `show_in_tooltip`, explicit removal, and hide-tooltip behavior are retained. Creative catalog slots use the native Creative tooltip flag; inventory slots do not bypass hiding.
- Item tooltips use the live server tag table. Old text/NBT formats stay in old targets, and 1.20.6 keeps components.

The [1.8 release history](https://minecraft.wiki/w/Java_Edition_1.8) records permission tooltips and their HideFlags bits. The [official 1.20.5 notes](https://www.minecraft.net/pl-pl/article/minecraft-java-edition-1-20-5) record the switch to components and their tooltip visibility. Exact native jars were used to resolve behavior within those broad version boundaries.

## 1.20.6 fallback registry correction

`default-tags.js` still identified its source as 1.19.4 and used that release's numeric IDs. In 1.20.6 this could put Nether Gold Ore in the logs group. The default table is now generated from the SHA-1-pinned 1.20.6 jar and native registry reports: 181 block tags, 147 item tags, 2 fluid tags and 29 entity tags. Nested references, optional entries, membership, duplicate removal and order are preserved. Server Tags packets still replace all fallback groups.

`tools/port-1.20.6/default-tags.mjs --check` is in the target gate. Runtime regressions verify source identity, all member ID domains, log/climbable/new item membership and server replacement. The other targets' default tables identify their own target releases; this 1.20.6 registry data is not copied to them.

## Native evidence and checks

`tools/ExtractAdventureTooltips.java` runs real ItemStack tooltip generation on each 1.8.9–1.19.4 jar, both normal and advanced. On 1.8.9/1.12.2 only the language-map values are set to their keys so native localized-name selection can be compared independently of English text. Native classes remain unchanged. The fixture generator verifies jar hashes and any downloaded native libraries. Permission/Unbreakable text and colors are compared; unrelated old tooltip sections are not claimed as fully accepted.

On 1.20.6, `ExtractAdventure1206` uses the real ItemStack codec and tooltip methods. Its 81 stack cases compare complete normal/advanced text and permission styles; five additional Creative contexts exercise the native Creative flag. Existing 49-stack item UX/style checks still pass. Native Property domains and default tags are regenerated by their existing gates.
