# Model-bundle cache provenance

Shared fix reviewed across all ten existing targets, 2026-11-17.

Prebuilt entity-model bundles previously remained eligible after an extractor or field-layout change within the same Minecraft release. This could serve an old model map after pulling new runtime code, including missing decorated-pot models or the older bat field layout.

Every builder output format now includes `bundles/entity-models-source.json`. It records a deterministic fingerprint of the model extraction code, JVM/bytecode helpers, native model/layer Java extractors and model-layer definitions, the actual client-jar SHA-1, and the model JSON's SHA-256. At proxy startup, the prebuilt entity-model bundle is accepted only when all three match. A missing/outdated stamp or truncated/changed bundle sends that request through the existing native model extraction path. The check occurs at startup, not per rendered frame. Restart the proxy after pulling code.

The helper applies to every existing named version, 1.8.9 through 1.20.6. It adds no later Minecraft feature, protocol field or GUI row to older targets. The older static middleware and the newer versioned-asset middleware both guard the entity-model endpoint; proxy-only behavior is preserved. This is model-bundle provenance, not a new authentication/signing protocol or a replacement for each target's other asset-cache rules.

All ten branches pass two cache regressions covering changed jars, changed extraction sources/layer fields, truncated content, missing stamps and unrelated documentation edits. Proxy and builder syntax checks pass on every target. The modern full native gate passes **492 tests**, zero failures/skips. Modern development assets were rebuilt with **128 models**, and their on-disk provenance stamp was independently checked against the actual pinned jar and bundle bytes. No native graphics/FPS or live gameplay metrics are inferred from these checks.

Use `npm run test:model-cache` on any target. `npm run assets`, packed HTML builds and complete static-site builds all generate the provenance file. Existing pre-fingerprint assets can be regenerated by the proxy's native extraction path, or rebuilt with the builder. Published all-version HTML/static distributions have not been regenerated by this source-maintenance batch.
