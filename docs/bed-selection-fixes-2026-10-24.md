# Beds, selection shapes, turtle eggs and portal reloads

Implemented 2026-10-24. Shared fixes are on 1.8.9, 1.12.2 and 1.13.2;
version-specific behaviour stays on its native version.

- Selection bounds are generated by running each pinned client jar's block shape
  methods. The data records the client jar SHA-1 and version, deduplicates boxes,
  and is loaded through the existing worker-safe block-shape data. The 1.13.2
  table covers all 8,599 registered states. Legacy versions use the extracted
  static bounds and retain the existing live-neighbour resolver for connected
  fences/panes/walls, stairs, doors, chests and other contextual shapes. Invalid
  metadata combinations and bounds requiring an unavailable World are omitted
  rather than replaced by guesses. Beds use the jar's full 1 x 9/16 x 1 selection
  box, independently of model bounds or the visible legs.
- Sleeping sets the player's 0.2 x 0.2 hitbox and bed-relative position, clears
  velocity and anchors the camera to the bed direction. The settled camera
  transform follows vanilla's sleeping branch, including its eye-height and
  translation offsets and cancellation of ordinary mouse-look rotations. The
  walking bob, first-person pullback and third-person chase offset do not shift
  the sleeping camera. This applies to all three versions.
- Placed bed textures in 1.13.2 use the colour in the block's identity, including
  `light_gray`. Older versions keep their own bed rendering: 1.12.2 colours come
  from block-entity NBT, and 1.8.9 has its original red bed.
- Turtle eggs in 1.13.2 are not opaque cubes. The terrain face beneath them stays
  visible, and `pushOutOfBlocks` no longer applies a sideways shove while the
  player steps onto or stands on the 7/16-high egg collision shape. No turtle
  egg feature is introduced on older branches.
- Native chunk-load scanning now creates the End portal surface renderer, as
  block changes already did. This fixes portal surfaces disappearing after a
  rejoin or chunk reload. Both older branches already scanned End portal blocks;
  regression coverage was added there too.
- The 1.13.2 global chunk palette has no palette-length header. The decoder now
  follows the jar's registry palette writer instead of consuming the long-array
  length as a palette header. A cross-long 14-bit section test verifies filled
  portal-frame states and their eye geometry survive decoding. The older
  versions retain their own packet layout.

Regenerate or verify the selection data with Java 11+ and the matching client jar:

```sh
MC_LIBRARIES=/absolute/path/to/vanilla-server.jar node tools/block-shapes/extract.mjs --write
MC_LIBRARIES=/absolute/path/to/vanilla-server.jar node tools/block-shapes/extract.mjs --check
```

`MC_LIBRARIES` supplies third-party dependencies. The client jar appears first on
its classpath, so Minecraft behaviour comes from the client. A library directory
classpath can also be supplied using the platform's classpath separator. Normal
client builds use committed generated data and do not require Java or a server
jar. Extraction runs in a temporary directory to contain vanilla bootstrap logs.

Run `node tools/test-client-regressions.mjs` on each version. Tests cover jar
provenance, bed bounds and textures, sleeping position in all four directions,
portal chunk reloads, every turtle-egg state, and global-palette frame states.
Live browser/server checks remain appropriate for camera feel and visual review.
