# Preloading, shader water/clouds and rendering review

Implemented on all nine existing supported branches (1.8.9 through 1.19.4), preserving each target's assets, loading screens, world bounds and native GUI rows.

Startup now keeps the splash until title/UI textures are decoded/uploaded, common non-streaming sound buffers are warm, and the saved shader pack has compiled. All six panorama faces are required. A generated texture index also warms entity, block-entity, sky and other non-atlas textures with four concurrent decodes and a 64 MiB decoded-image budget; block/item atlases already load during startup. Resource-pack PNG overrides participate. Oversized textures, remaining Unicode pages, music and uncommon sounds still stream on demand. This deliberately does not preload every possible asset. In-flight image reads are deduplicated and discarded across resource reloads; linear/nearest uploads have separate keys. Extras offers a world texture preload toggle.

The synthetic MinecraftJS cloud layer and sinusoidal water waves were removed after the user's correction. Their Extras buttons were removed, along with the old approximate water-reflection and lightmap overrides. Imported packs must supply their actual effects; no substitute sky/water is installed automatically.

The real post-stage path discovers per-dimension deferred/composite programs, compiles their own GLSL and vertex programs, and executes them in numeric order through ping-pong targets before final. It honors literal program-enable flags and stage-specific texture bindings. Only actual scene colour (`colortex0`/`gcolor`) and captured depth can be supplied. Missing material, shadow, history and other colour attachments are errors, not aliases to ordinary scene colour. A failed chain import keeps the previous working pack/resources. Dimension-specific unsupported stages disable the pack with a diagnostic. A tooltip on the shader screen's status lists real running and unsupported stages.

**Full BSL/Complementary/Photon rendering is unfinished.** BSL's final currently needs its true `colortex1` and Complementary needs `colortex3`; the earlier bridge simply aliased these to scene colour. That misleading fallback is removed, so those archives now report an unsupported buffer rather than pretending to render correctly. Photon also requires additional pipeline stages. Final-only and scene-colour/depth post packs are supported. Genuine vegetation functions remain available for compatible packs. These capabilities are not full arbitrary OptiFine shader compatibility. There is no new sky/cloud/water toggle in Extras; those effects belong to the pack's settings once its actual pipeline is supported.

## Real shader pipeline remaining work

1. Build attachment/format/clear/mipmap plans from pack properties and render-target directives. Implement genuine MRT routing and ping-pong histories, with framebuffer-completeness and capability errors. Do not substitute missing buffers or disable requested effects silently.
2. Bind actual geometry attributes/matrices (normal/tangent, material ID, mid-texture coordinates, lightmap) to the pack's terrain/entity/water programs. Preserve independent solid/cutout/translucent submission and depth snapshots.
3. Execute the pack's own sky programs and shadow geometry passes with native sun matrices, actual shadow textures and comparison samplers. Then execute deferred/composite stages with their true inputs. Support pack custom-uniform expressions and lifecycle/resize/resource reload.
4. Verify BSL first, then Complementary/Photon, across dimensions and time/weather/settings. Compare actual source stages and image captures with a reference shader client; full reference-client image validation is not yet available. Add per-feature browser/GPU regressions before enabling a capability.
5. Backport the completed renderer support to existing targets while preserving native world bounds and asset/GUI differences. Software/WebGPU should report unsupported shader capabilities until their own real implementations exist.

## Rendering investigation

- [Sodium RenderSectionManager](https://github.com/CaffeineMC/sodium/blob/dev/common/src/main/java/net/caffeinemc/mods/sodium/client/render/chunk/RenderSectionManager.java) separates camera/graph updates from reusable render lists. Applied that principle: cache visibility walk and near-to-far sorting only while every camera, frustum, fog, culling and world-bound input is identical. Geometry/column changes invalidate it. Both terrain and entity visibility retain the last completed culling graph. Also removed the duplicate per-frame sort and unused fast-cloud mesh uploads. No source was copied from Sodium.
- [Sodium occlusion culler](https://github.com/CaffeineMC/sodium/blob/dev/common/src/main/java/net/caffeinemc/mods/sodium/client/render/chunk/occlusion/OcclusionCuller.java) and [chunk renderer](https://github.com/CaffeineMC/sodium/blob/dev/common/src/main/java/net/caffeinemc/mods/sodium/client/render/chunk/ChunkRenderer.java) suggest the next larger rendering step: region mesh arenas and batched submissions. Before implementing, measure draw submission time and section rebuild costs on real browser GPUs; preserve translucent ordering and resource lifetimes. WebGL multi-draw is optional, so keep a baseline path. This step is not implemented here.
- [Lithium](https://github.com/CaffeineMC/lithium) improves simulation and collision work, rather than replacing the renderer. Profile entity/collision queries separately before changing their native behavior.
- [Starlight technical details](https://github.com/PaperMC/Starlight/blob/fabric/TECHNICAL_DETAILS.md) and [Phosphor](https://github.com/CaffeineMC/phosphor-fabric/blob/1.19.x/dev/README.md) concern lighting propagation/storage. This client receives authoritative server light arrays; importing a server light engine is not an automatic rendering win. A useful future measurement is dirty-neighbour propagation and remeshing after light-only packets. Neither engine is ported here.
- [OptiFine](https://optifine.net/home) documents configurable chunk updates, preloading, fog and animation controls. Apply bounded queues/preloading and visibility-aware work after profiling; do not assume its JVM/desktop OpenGL synchronization techniques fit browser drivers.
- The requested modpack is [Fabulously Optimized](https://github.com/Fabulously-Optimized/fabulously-optimized), a collection of mods rather than another standalone renderer. Its component list is useful for choosing separate profiling targets.

The existing code already uses mesh workers, atlases, packed terrain vertices, graph/frustum/fog culling and mesh LOD. Avoid replacing these merely to mirror a mod's name. Next profile CPU visibility/submission, worker rebuild latency, texture uploads, overdraw and GPU frame time separately. Actual desktop GPU/FPS and JVM profiler numbers are unavailable from this headless run.

## Validation

`tools/test-preloading.mjs`: concurrency, budgets, GPU uploads, image dedup/reload epochs, texture filtering and short sound warmup.
`tools/test-visibility-cache.mjs`: exact-input cache behavior, failures, and real Renderer mesh replacement/removal invalidation.
`tools/test-shader-post-stages-browser.mjs`: actual multi-stage GLSL pixel output/order, dimension overrides, disabled stages, unavailable-buffer rejection and rollback/resource disposal.
Existing loading/extras, final/depth, genuine vegetation and explicit BSL unsupported-buffer checks run across the affected targets. Standalone legacy reflection/lightmap helpers are no longer automatically injected into imported packs.

`tools/benchmark-visibility-cache.mjs` measures 200 repeated stationary-camera walks/sorts over 4,624 synthetic sections. A recorded Node v22.23.3 run took 173.835 ms without reuse and 0.203 ms for cached lookups after one initial walk (200 cache hits). This isolates CPU visibility work, excludes the initial walk from cached timing and is not a whole-frame FPS claim. Camera motion or geometry changes cause a fresh walk. Re-run locally; results depend on machine/load.

Source archives inspected directly: supplied BSL v10.1.8 and cached upstream Complementary Reimagined/Photon. The stage files establish why real water/cloud rendering needs a complete render graph, not a generated replacement effect. No vendor shader source was copied into the repository; only original small test fixtures are committed.

The stage/attachment requirements were checked against the [OptiFine shader interface](https://github.com/sp614x/optifine/blob/master/OptiFineDoc/doc/shaders.txt), [shader properties](https://github.com/sp614x/optifine/blob/master/OptiFineDoc/doc/shaders.properties) and [Iris DRAWBUFFERS documentation](https://shaders.properties/current/reference/constants/drawbuffers/). Each colour attachment is independent; a post pass cannot obtain a missing attachment by renaming the scene texture.
